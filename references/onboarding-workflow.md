# 一次对话完成首次设置

用于用户明确要求“带我完成首次设置”“帮我开始使用”。一次对话不是一次无条件授权：复用已有信息，逐步完成目录、画像、试跑和可选调度，不要求用户依次复制多份长提示词。

## 1. 从缺失项开始

先简述本次流程，并使用用户已指定的学习目录；目录未知时只问目录，不扫描主目录。确认路径后可创建 `repos/`、`reports/`、`articles/`、`state/`，不运行安装脚本。

读取该目录中已确认的 `learning-profile.md` 和相关设置记录。已有画像直接复用，不因第一次调用本版本就重建。当前明确请求优先于旧记录；旧记录用于恢复进度，不是新的权限凭证。

只安装、介绍能力、修改 Skill 或补写指南时不开始本流程。用户只要研究、文章或画像时走对应入口，不强制完成全套设置；无人值守运行不发起交互式引导。

## 2. 按已有画像或授权继续

缺少画像时按 [画像初始化](profile-workflow.md) 检查工具能力，再询问有限的读取范围；不先调用聊天列表。可建议最近 30 天、技术学习相关内容，但必须确认真实日期范围、时区和预算后才读取。

不愿授权或没有工具时，改为用当前对话填写必要信息：关注方向、熟悉语言、一个近期问题和可用学习时间。能从当前明确回答获得的信息不重复问；未知项保留未知，不把模板示例当真实画像。

展示候选摘要、推断项和差异，用户确认后才保存。没有确认就停在候选阶段，不继续个性化试跑，不创建定时任务；用户明确接受通用研究时另行标明其非个性化性质。

## 3. 做一次小规模试跑

请求已包含“确认画像后试跑一次”时不重复征求研究授权；只要求设置且未授权试跑时，先询问是否开始。按 [研究流程](research-workflow.md) 在同一目录、实际可用权限下运行，复用历史记录和已确认副本；预算用用户已给的值，没有则说明采用 Skill 默认规模。

只产出研究报告、真实快照、运行记录和最小实验建议，不运行项目或实验，不默认写长文。结束时给出可核查的文件位置、画像相关性和证据边界。

报告为 `partial` 时保留缺口，不把它改写成完整成功。无法产出可核查报告、画像未确认或存在阻止复跑的环境问题时，先说明阻碍，不将本次试跑当作已经适合无人值守运行。

## 4. 主动邀请，但不静默启用

首次设置的试跑产生可用结果、没有阻止复跑的关键问题后，主动询问一次是否开启定时学习，不等用户再寻找配置命令。先披露仍存在的 `partial` 范围；用户已明确请求定时则直接补齐缺失参数，不再泛问是否需要。

可使用简短问法：“这次报告已保存。要不要以后按固定时间在本聊天继续？如果需要，请告诉我频率、时间和时区；我会先确认完整计划再创建。”已知的时间、目录、预算与结果位置不重复问，通知设置沿用已确认值，不承诺额外推送渠道。

- 用户拒绝或选择以后再说：结束设置，记录选择；以后普通研究不反复推销定时。只有用户重新提出定时或明确要求重新设置才继续。
- 画像明确禁止创建定时：说明当前保持未启用，不把同意首次设置当作解除禁令；只有用户明确变更该项授权才进入配置。
- 客户端没有调度工具：说明只能手动运行，可提供说明；不伪造已创建任务，不安装后台服务，不写私有调度配置。
- 只是同意了解定时、继续设置或采用某个时间：不等于同意创建。展示频率、时间、时区、目录、输出位置与范围后，确认是否现在创建；用户已明确授权这份完整计划时不要机械重复询问。

收到对具体计划的创建授权后，转入 [定时配置](automation-workflow.md)，查重并使用真正的调度工具。创建后回显实际任务 ID、状态、计划、时区和执行目录；工具失败、超时或返回不完整时如实保留未确认项，先核查而不是盲目重试。任务创建成功与未来按时运行、通知送达是不同结论。

## 5. 可恢复、可核查地结束

按 [状态约定](state-format.md) 在 `state/runs/` 保存本次设置阶段、已确认事项、试跑记录引用、是否已邀请定时及用户选择。每次续做生成新记录，保留旧记录；不保存聊天全文或把状态文件上传到公共仓库。

中断后只补未完成项，不重读历史、不重复试跑或创建已存在的任务。遇到创建结果不明，先通过调度工具核查；不能仅凭记录中的“已同意”再次创建。

最终给出四项清单：画像是否确认、试跑产物、定时是否真实创建、仍需用户处理的事项。没有真实任务 ID 和计划确认时，明确写“定时未创建”或“创建结果待核查”，不用“明天会自动推送”代替事实。
