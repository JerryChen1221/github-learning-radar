# 定时学习配置

区分“文章里描述定时方案”和“请现在创建定时任务”。只有后者进入实际配置；调用 Skill、生成图文或提供示例时间都不自动授权创建。

## 环境与计划

1. 核实频率、运行时间、时区、学习目录、输出阶段与权限。默认保持每日研究规模；只有用户要求才每次生成长文。不自动做网页保存或发布。
2. 核实当前客户端的自动化能力和官方文档，不凭旧版本假定云端能读取本机文件。需要本地项目的任务依赖机器开机、应用运行、路径和网络可用。
3. 优先使用环境的自动化管理工具。当前聊天内持续执行优先选其支持的同聊天任务；只有用户明确要每次新聊天或独立项目作业时，才选独立任务。
4. 检查是否已有同用途任务，优先更新，保留未被要求修改的时间、模型、项目和通知设置，不创建重复任务。
5. 如关键参数缺失，仅询问缺失项；例如“每日 08:30”是范例，不得擅自当成用户时区或意愿。

工具不存在时给出可复制配置和环境要求，标注“未创建”。不绕过客户端去改自动化私有文件、系统 crontab 或后台守护进程。

## 先手动验证

在同等文件和网络权限下验证研究阶段，确认 Skill、画像、快照均可访问。不要拿另一个工作区或更高权限的成功当作验证通过。worktree 模式不能假定未提交画像或历史自动同步。

有未解决的环境阻碍时不要宣称已能连续运行。用户要求保留未启用配置时用工具实际支持的暂停状态，并明确仍需验证。

## 调度提示词示例

把目录和阶段替换为真实已确认值；定时任务调用的是研究流程，不是再次建立定时器：

```text
使用 $github-learning-radar，在已指定学习目录完成本次项目研究。
读取 learning-profile.md 和历史 state；先按当前问题筛选，再参考热度。
遵守约定候选和深读预算，记录真实 Star 观测，不把无基线当成日增。
保存独立报告、快照和运行记录；无新发现允许跳过，不覆盖旧结果。
只做静态源码研究和实验建议，不运行下载项目，不修改业务代码。
不读取未授权聊天、不对外发送报告、不操作网页、不创建其他定时任务。
```

若用户要求定时生成本地图文，可补充文章阶段和明确产物目录。不能顺带取得发布权限。通知设置通过工具的专门字段配置并遵守当前工具约定，不把不支持的通知行为写成保证。

## 保存与核实

按工具所需授权创建或更新后，读取实际返回的任务 ID、状态、时间计划、时区、执行位置和提示词。只称工具已确认的部分；无法核实时说明限制，不预测下一次必定成功。

将实际配置记录到本次 `state/runs` 的自动化阶段。再次调用研究任务不得递归创建调度器。能力安装包不包含个人自动化 ID、用户目录或账号配置。

官方资料（配置时重新核实）：[Scheduled Tasks](https://learn.chatgpt.com/docs/automations?surface=app)、[Build Skills](https://learn.chatgpt.com/docs/build-skills)。
