# SVG 配图规范

图只解释正文中的一个关系，不为装饰堆图。可选形式：步骤流程、职责架构、同层产品比较、证据到实验的反馈。数量和结构按内容决定。

## 现代 SaaS / Tailwind UI 视觉

- 使用浅色背景 `#f8fafc`、白色卡片、细边框 `#e2e8f0`，靛蓝 `#4f46e5` 与青绿 `#0d9488` 少量强调。
- 画布通常宽 1200，圆角卡片与一致间距，阴影克制；这是视觉风格，不需要安装 Tailwind。
- 每张图一个主标题，一句说明；正文文字建议 22—28，标题 34—40，最终以文章宽度下的可读性为准。
- 每张卡片最多一个标题、两行补充。长中文手动分行，避免文字溢出、线穿字、箭头方向不明。
- 使用 SVG 原生文本与图形，包含 `viewBox`、`title` 和 `desc`；不嵌入脚本、远程资源或 `foreignObject`。保留可编辑文字，不用截图替代 SVG 源文件。

## 可复用底稿

- [学习流程底稿](../assets/learning-workflow.svg)：适合讲发现、筛选、源码、比较、个人关联与实验。图中数量是默认起步预算，须与本次正文一致。
- [职责架构底稿](../assets/reusable-setup.svg)：适合讲定时器、画像、历史、Skill 与产物的分工。时间只是例子，不代表已配置任务。

底稿不是通用项目架构图；具体项目要根据证据改节点和连线，不能把未实现能力画成现有组件。复制到本次文章目录后修改，不改安装包里的底稿。

## 渲染与验收

优先使用当前环境已有的 SVG 渲染器或工作区图像库。需要平台兼容图时输出 PNG，通常使用 2 倍分辨率；不静默安装依赖，不宣称某网站必然支持 SVG。

实际查看渲染结果，再放到文章预览中检查。中文字体、文字裁切、箭头和缩放可读性都要验证。没有可用渲染能力时可以交付 SVG，明确“尚未做渲染检查”，不要编造 PNG 或验证结果。

SVG 源文件留在素材包；网页是否用 SVG 或 PNG 由编辑器实际能力决定。给图片提供说明文字，避免关键信息只存在于图中。
