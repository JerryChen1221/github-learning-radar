# 学习报告约定

报告使用用户的语言，通常控制为一份能在 10—15 分钟内读完的材料。以下是内容要求，不要求机械保留全部标题；没有重要变化时可以简报代替深读。

## 1. 本次结论

先写最值得读的一个项目和选择原因，明确它对应画像中的哪个问题。不要以最高 Star 自动决定深读对象。

## 2. 候选与口径

用简表列出实际获取的候选、累计 Star、观测时点、与问题的关联、来源。日增未知就写未知；多日净变化要注明起止时点。没有完成广泛搜索时说明本次是定向名单，不称为完整热榜。

## 3. 深读项目

- 一句话定位；实际适用场景；不在其职责内的事情。
- 规范仓库地址、固定 commit、获取方式及本地研究目录。
- 一条关键调用链或机制，至少给出足以支持结论的文件/符号证据。
- 主要失败、权限或验证边界，不将声明等同于代码事实。

## 4. 两个相关方案

比较共同能力、层次、设计侧重点、使用前提及局限。若只是文档级比较，明确说明没有深读对方实现；不同层次不能直接评选完全替代关系。

## 5. 对我的意义

把一个设计对应到画像中的一个问题，写明可以借鉴什么、不应照搬什么。

## 6. 一个小实验

说明实验目标、最小范围、步骤和可观察的验收条件。注明实验是否真正执行；本 Skill 默认只提出实验，不执行下载项目。

## 7. 证据与未完成事项

列公开一手来源及固定提交链接；正文就近标注来源。说明是否拉取了源码、是否运行测试，以及来源受限或尚未验证的内容。不给用户展示凭据或内部原始数据。

同次运行的记录和 Star 快照放在 `state` 中，不把大段机器 JSON 塞进报告正文。
